# 원천세 지급관리 ↔ 더존(비즈박스) 연동 프로그램

경영기획실 PC에서 돌면서 그룹웨어의 지출결의서(계좌이체)를 읽어 웹앱에 보내고, 웹앱이 지급요청에 품의번호(지결번호)를 적습니다. 이 저장소에는 코드만 있고 연동 키·그룹웨어 비밀번호는 들어 있지 않습니다(키는 설치 때 config.json 에 적고, 그룹웨어 로그인은 브라우저 창에서 직접 합니다).

## 설치 (git 방식, 권장)
1. 기존 원천세연동 폴더가 있으면 그 안에 `원천세연동_git설치.bat` 을 넣고 더블클릭합니다(기존 config.json·로그인 상태를 그대로 옮겨 옵니다). 처음 설치라면 아무 폴더에 넣고 더블클릭합니다.
2. git 이 없으면 자동으로 설치되니, 창을 닫고 같은 파일을 한 번 더 더블클릭합니다.
3. 질문 세 개(수신 주소·연동 키·자동 실행 시각)에 답하면 작업 스케줄러에 두 가지가 등록됩니다: 5분마다 연동 확인, 매일 08:50 자동 업데이트(git pull).
4. `연동 시험.bat` 으로 그룹웨어에 한 번 로그인하고, `지금 더존과 연동.bat` 으로 첫 전송을 확인합니다.

이후 프로그램이 바뀌면 다음 날 아침 자동으로 받아지며, 바로 받으려면 `업데이트.bat` 을 더블클릭합니다. 파일을 손으로 복사할 일이 없습니다.

# 더존 비즈박스 알파 → 원천세 지급관리 연동 프로그램 (경영기획실 PC용)

그룹웨어(https://gw.openknowl.com)의 전자결재에서 **상신된 지출결의서(계좌이체)** (결재 중·종결 모두)를 읽어 웹앱에 보내면, 웹앱이 **최종 결재권자까지 승인(종결)된 문서**만 금액·사업명·날짜로 지급요청을 찾아 **품의번호(지결번호)** 를 자동으로 적습니다. 결재 중인 문서는 보류하고, 반려·회수된 문서의 번호는 요청에서 비웁니다. 지급일자는 경영기획실이 엑셀을 내려받은 뒤 적습니다.

## 설치 (경영기획실 PC, 한 번)

1. 이 `connector` 폴더를 경영기획실 PC에 둡니다. 두 가지 중 하나:
   - **git 으로 받기(권장, 나중에 "업데이트.bat" 한 번으로 최신화)**: Git for Windows 를 설치하고 명령 프롬프트에서 `git clone https://github.com/jykim-sada/sangsangwoori-tax-payment-management.git C:\원천세` (처음 한 번 GitHub 로그인 창이 뜸) → `C:\원천세\connector` 가 이 폴더입니다.
   - **ZIP 으로 받기**: GitHub 저장소 → Code → Download ZIP → 압축을 풀고 `connector` 폴더만 PC에 복사. 업데이트는 같은 방법으로 다시 받아 덮어씁니다(config.json·bizbox-state.json 은 남김).
2. **install.bat** 을 더블클릭합니다. 순서대로 진행됩니다.
   - Node.js 가 없으면 설치를 시도합니다(안 되면 https://nodejs.org 에서 LTS 설치 후 다시 실행).
   - 필요한 모듈과 크롬(playwright)을 설치합니다.
   - 질문에 답합니다: 웹앱 수신 주소, 연동 키(웹앱 관리 → 데이터 → 더존 연동 → "보기"), 매일 자동 실행 시각(기본 9시). 그룹웨어 아이디·비밀번호는 묻지 않고 저장하지도 않습니다.
   - Windows 작업 스케줄러에 "원천세 더존 연동"(5분마다 `dozone-sync.js --auto`)을 등록합니다.
3. **연동 시험.bat** 을 더블클릭하면 브라우저 창이 뜹니다. 그 창에서 그룹웨어에 직접 로그인(2차 인증까지)합니다. 3분 안에 로그인되면 프로그램이 그 상태를 `bizbox-state.json` 에 저장하고 짝짓기 결과를 보여 줍니다(웹앱에는 반영하지 않음). 이후 자동 실행은 저장된 로그인 상태를 재사용하며, 만료되어 "로그인 상태가 없거나 만료" 오류가 나면 같은 파일을 다시 더블클릭해 로그인합니다.
4. 끝. 이후에는 다음 두 가지로 돕니다.
   - **매일 오전 9시**(설정한 시각)에 자동으로 한 번: 전날까지 최종 승인(종결)된 지출결의가 품의번호로 들어갑니다. 그 시각에 PC가 꺼져 있었으면 그날 처음 켜진 뒤 5분 안에 한 번 돕니다.
   - 웹앱 관리 → 데이터 → **지금 더존과 연동** 버튼을 누르면 5분 안에 한 번 더 돕니다. PC에서 바로 돌리려면 **지금 더존과 연동.bat**.

**무엇이 자동으로 바뀌고 무엇이 아닌가**: 웹앱(화면·짝짓기 규칙·입력표)은 배포하는 즉시 모든 사용자에게 적용되므로 PC에서 할 일이 없습니다. 이 PC의 연동 프로그램(그룹웨어 읽기·전송 방식)만 로컬 복사본이라, 그 부분이 바뀌면 **업데이트.bat** 을 더블클릭해 최신으로 맞춥니다(git 으로 받은 경우 `git pull` + `npm install`; ZIP 으로 받은 경우 다시 내려받아 덮어쓰기). 설정과 로그인 상태는 그대로 남습니다.

기록은 `sync.log` 에 쌓입니다. 설정을 바꾸려면 `node setup.js` 를 다시 실행하거나 `config.json` 을 고칩니다. 스케줄을 지우려면 작업 스케줄러에서 "원천세 더존 연동"을 삭제합니다.

## 무엇을 읽나

- 목록: 전자결재 전체결재문서(EaTotalDoc, 메뉴 2002140000)의 최근 60일 문서 중 양식이 `지출결의서(계좌이체)` 이고 제목에 기타소득·사업소득·원천이 들어간 문서(**상신된 것 전부**: 결재 중·종결·반려. config 의 docSts 에 "90"을 적으면 종결만)
- 상세: 각 문서 화면의 금액(실지급액 + 원천세 = 총액이 되는 숫자 묶음). 짝이 맞고 **최종 결재권자까지 승인(종결)된 문서만** 품의번호가 들어가고, 결재 중·임시저장 문서는 보류, 반려·회수·삭제된 문서는 그 번호가 적힌 요청의 품의번호를 비웁니다. 지급일자는 앱이 채우지 않습니다(경영기획실이 다운로드 후 기재). 시행일자는 참고용으로만 보냅니다.
- 속도: 한 번 읽은 문서는 `bizbox-cache.json` 에 문서번호·상태와 함께 기억해 두고, 다음 실행부터는 새로 올라왔거나 상태가 바뀐 문서만 엽니다(처음 한 번만 몇 분, 그 뒤로는 보통 1분 안). 문서 3건을 동시에 읽고 진행 상황을 창에 "읽는 중 n/N"으로 표시합니다. 이 파일을 지우면 다음 실행 때 전부 다시 읽습니다.
- 보내는 값: 품의번호(문서번호), 제목, 총지급액, 기안일, 시행일, 상태, 기안자, 기안부서

## 자주 묻는 것

- **그룹웨어 비밀번호는 어디에 저장되나?** 저장하지 않습니다. 담당자가 브라우저 창에서 직접 로그인한 상태(쿠키)만 `bizbox-state.json` 에 남고, 웹앱으로는 아무것도 가지 않습니다.
- **짝이 안 맞는 건은?** 웹앱 관리 → 데이터 → 더존 연동 카드의 최근 결과와 `sync.log` 에 "못 찾음"으로 남습니다. 작성 목록에서 직접 품의번호를 적으면 됩니다.
- **한 지결에 여러 요청을 합쳐 올리면?** 제목에 사업명이 있고 총지급액 합이 지결 금액과 같은 요청 묶음이 하나뿐이면 그 전부에 같은 품의번호가 들어갑니다(같은 사업의 기타소득+사업소득 합산 포함). 사업이 둘 이상이면 제목에 사업명을 모두 적어야 하고, 합이 같은 묶음이 여럿이면 보류됩니다.
- **그룹웨어 화면이 바뀌면?** 목록은 JSON 호출이라 영향이 적고, 상세의 금액은 라벨이 아니라 "실지급액 + 원천세 = 총액"이 되고 원천세 비율이 8.8%(기타소득) 또는 3.3%(사업소득)인 숫자 묶음으로 찾으므로 표 모양이 바뀌어도 숫자가 화면에 있으면 동작합니다.


## 읽는 범위 (v66)
최근 60일의 지출결의서(계좌이체) 전부를 읽어 웹앱에 보냅니다. 제목으로 거르지 않습니다(제목 필터를 쓰려면 config.json source 에 "titleFilter" 와 "titleFilterStrict": true 를 함께 적습니다). 어느 요청에 적을지는 웹앱이 금액·사업명·지급 대상 성명·가져온 파일명·날짜로 정합니다.


## 그룹웨어 로그인 유지와 상태 표시 (v67)
`--auto` 실행은 10분마다 저장된 로그인 상태로 그룹웨어에 들어가 봅니다(세션 연장). 만료됐으면 웹앱의 더존 연동 카드에 "그룹웨어 로그인 만료"로 표시되고, 노트북에서 "연동 시험.bat"으로 다시 로그인하면 보류됐던 연동이 이어서 돕니다. 노트북 상태(마지막 신호·로그인·마지막 실행·오류)는 같은 카드에서 볼 수 있습니다. 상태는 같은 폴더의 .state.json 에 남습니다.
